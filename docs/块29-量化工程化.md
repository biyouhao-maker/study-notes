# 块29 · 量化工程化：给回测引擎装上测试和安全带

> 2026-11-04 凌晨。前 28 块证明了策略思想，这一块解决"代码能不能信"的问题。

## 29.1 为什么回测引擎必须有单元测试

回测是所有结论的地基，而回测代码的 bug 有个阴险的特点：**它不报错，只是安静地给出错误数字**。费用算错一个数量级、动量基准日偏移一天、波动率用错年化系数——曲线照样画得漂漂亮亮。块 14 讲过财报造假信号，回测代码的 bug 就是"自己给自己造假"。

解法是三个工程动作：

1. **模块拆分**：把"会不会算"（纯函数）和"能不能联网取数"（数据层）拆开——`quant_core.py` 只做计算，`quant_data.py` 只管数据，互不依赖。
2. **TDD**：先写测试再写实现。21 个测试全部用**合成数据 + 手工计算期望值**，零网络、0.1 秒跑完。
3. **金标准测试（Golden Master）**：重构前先把旧版输出抄下来当基准，重构后逐数字对比。

## 29.2 模块划分

| 模块 | 职责 | 可测性 |
|---|---|---|
| `quant_core.py` | 月末提取、动量、绝对动量门、波动率目标、费用、回撤 | 纯函数，全覆盖 |
| `quant_data.py` | 腾讯 hfq 抓取（分页）+ 本地 JSON 缓存（TTL 12h） | fetcher 可注入，测试零触网 |
| `backtest_engine_a.py` | 只剩编排：读数 → 逐月调仓 → 统计 | 金标准对比验收 |

数据层的两个关键设计：**fetcher 可注入**（测试传假 fetcher，断言"缓存新鲜时绝不触网"）；**缓存原子写入**（先写 `.tmp` 再 `os.replace`，断电不产生半截缓存）。

## 29.3 金标准测试的实战演示

重构完成后跑回测，结果：

- 2013-07 至 2026-09 的**每一个月度收益与重构前逐格一致**，历史最大回撤 -18.53% 分毫不差 → **重构正确**。
- CAGR 7.92%→7.76%、胜率 61.3%→60.9% 的微小漂移，来自 5 天里新增的两个交易日（10-30、11-03）——**数据漂移，不是代码漂移**。

学会区分这两种漂移，是量化工程师和"调参侠"的分水岭。

## 29.4 真实的安全审计课：路径穿越

本次写 `quant_data.py` 时被安全工具（Mimosa）连续拦截四次"路径穿越高危"：缓存文件名由 `symbol + beg` 动态拼接，若 `beg` 传入 `../../etc` 就能写到仓库外。最终修复三件套：

1. `symbol` 和日期过严格正则（`^(sh|sz)\d{6}$`、`\d{4}-\d{2}-\d{2}`）——组件里**不可能**出现 `..`；
2. `realpath` 后边界检查：路径必须仍在缓存目录内；
3. 临时文件同样过检查，`os.replace` 原子替换。

教训：安全工具拦下来的每一次，都是块 19"供应链安全"的现场教学。

## 29.5 CI 接入

`.github/workflows/ci.yml` 新增 pytest job：`pip install pytest && python -m pytest -q`——21 个测试在 GitHub 的 ubuntu runner 上 10 秒跑完。从此**每次 push，CI 自动验证 21 个断言**；谁改坏了动量计算，绿标变红，不用等人发现。
