## 32.1 先动手：nanoGPT 的解剖课

Karpathy 的 [nanoGPT](https://github.com/karpathy/nanoGPT)（**注意：2025-11 起已标记弃用，继任者 [nanochat](https://github.com/karpathy/nanoGPT) 完整链路可训到能聊天**）仍是最教学内容：`model.py` 只有约 330 行，结构是一个标准 decoder-only Transformer：

- `GPTConfig` 四个关键超参：`n_layer`（堆多少个 Transformer 块，12）、`n_head`（每个块里几组注意力头，12）、`n_embd`（隐藏维度，768）、`block_size`（上下文窗口=位置表大小，1024）。
- 每个块 = **pre-norm 残差**：`x = x + Attention(LN(x))`，然后 `x = x + MLP(LN(x))`——残差是"信息高速公路"，LayerNorm 放进支路里稳定训练。
- 注意力：一个 `Linear(n_embd → 3*n_embd)` 融合出 Q/K/V（一次矩阵乘省三次），PyTorch 2.0+ 自动走 flash attention；因果性靠下三角 mask——**每个 token 只能看它左边的历史**。
- MLP：4 倍升维 + GELU；权重共享（输入嵌入 = 输出头）；初始化按 `0.02/√(2·n_layer)` 缩放（块堆得越深，残差流越要"轻放"）。

**最小可运行路径**（Colab 免费 CPU 就能跑）：`data/shakespeare_char/prepare.py`（文本→整数流）→ 训练配置 block 256 / n_embd 384 / 6 层 6 头 / 5000 iters，约 10.7M 参数，A100 三分钟、CPU 慢些也能收敛；再 `sample.py` 生成莎士比亚味的文本。配套视频 [Let's build GPT](https://www.youtube.com/watch?v=kCc8FmEb1nY)（1h37m）的教学顺序：bigram 基线 → 平均池化 → 单头自注意（Q/K/V、1/√d 缩放）→ 多头 → 前馈 → 残差 → LayerNorm → 放大。

## 32.2 Software 2.0 → 3.0：编程范式在换挡

- **Software 1.0**：人类写显式代码。
- **Software 2.0**（Karpathy 2017）：**权重即程序**——程序员的工作变成提供"数据集 + 目标函数 + 优化器"，由搜索隐式编程。代码不在任何编程语言里，但它在跑。
- **Software 3.0**（Karpathy 2025，YC AI Startup School）：**自然语言成了新的编程语言**。他的比喻：LLM 是新计算机的 CPU，上下文窗口是 RAM，token 计费像电力公用事业；我们正处在"LLM 的 1960 年代"；产品的核心设计变量是"自主性滑块"——给 AI 多大权限，人在回路验证到什么程度。

对块 18 的呼应：Navial 说"代码与媒体是无需许可的杠杆"，Karpathy 补上了后半句——**杠杆的燃料是数据与算力，方向盘是你写的提示与验证流程**。

## 32.3 Agent 与 MCP：你正在用的东西的原理

MCP（Model Context Protocol，Anthropic 2024-11 开源）是 AI 应用与外部工具之间的 USB-C：

- **架构**：host（如 ZCode/Claude Desktop）为每个 **server** 建一个 **client**，消息走 JSON-RPC 2.0，传输分 stdio（本地）与 Streamable HTTP（远程）。
- **服务器三类原语**：tools（可执行动作）、resources（可读数据）、prompts（可复用模板）；2026-07 版规范中 sampling 已被弃用。
- **解决的核心问题**：M 个应用 × N 个数据源原本要 M×N 个定制连接，标准协议把它降为 **M+N**——每方只需实现一次。
- **Agent 循环**：模型读上下文 → 决定调用哪个工具 → 工具结果回灌上下文 → 再决策，直到完成。你今晚看到的一切（搜索代理跑 13 路、git push、pytest）就是这个循环在转。

## 32.5 安全底线（对应块 19 的 AI 版）

- **提示注入是 OWASP LLM Top 10 的 LLM01**（2025 版区分直接/间接注入，官方明言现有防御无法完全缓解）——所以 agent 的工具权限必须最小化，这就是为什么块 29 的路径校验和块 19 的域名白名单不是过度设计。
- **幻觉对应 LLM09**：工程对策是 RAG（Lewis et al. 2020）+ 引用溯源 + 输出校验。金融语境的对应物就是块 11 的"一手材料优先"——让模型给引用，自己去巨潮/交易所验证。
